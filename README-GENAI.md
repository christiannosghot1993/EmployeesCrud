# Generative AI Assisted Development - Task Management REST API

## Overview

This document demonstrates how Generative AI was used to design and generate a RESTful API for a Task Management System. The exercise includes:

- The prompt provided to the AI coding assistant.
- A representative sample of the generated code.
- The validation process used to verify the generated solution.
- Improvements made to the generated output.
- Handling of authentication, authorization, validation, and edge cases.

The objective was not only to generate code using AI, but also to demonstrate engineering judgment by reviewing, validating, and improving the generated solution before considering it production-ready.

---

## 1. Prompt Used with the GenAI Coding Tool

For this exercise, a Generative AI coding assistant such as GitHub Copilot, Cursor, Claude Code, or Windsurf was used to generate the initial implementation.

### Prompt

```text
Generate a complete RESTful API for a Task Management System using ASP.NET Core 8 and Entity Framework Core.

Requirements:

- Implement CRUD operations for Tasks.
- Each Task must contain:
  - Id (Guid)
  - Title
  - Description
  - Status (Pending, InProgress, Completed)
  - DueDate
  - UserId

Architecture:
- Follow Clean Architecture principles.
- Use the following layers:
  - Domain
  - Application
  - Infrastructure
  - API

Implementation details:
- Use Entity Framework Core with Code First approach and Migrations.
- Create DTOs for requests and responses.
- Implement Repository and Service patterns.
- Include Controllers with RESTful endpoints.
- Add FluentValidation for request validation.
- Implement JWT Authentication and Authorization.
- Users can only access and manage their own tasks.
- Add Swagger/OpenAPI support.
- Include structured exception handling middleware.
- Return appropriate HTTP status codes.
- Include unit tests for the Application layer.

Generate all necessary entities, DTOs, repositories, services, controllers, validations, and sample unit tests.
```

### Tasks Controller

```csharp
[ApiController]
[Route("api/tasks")]
[Authorize]
public class TasksController : ControllerBase
{
    private readonly ITaskService _taskService;

    public TasksController(ITaskService taskService)
    {
        _taskService = taskService;
    }

    [HttpGet]
    public async Task<IActionResult> GetAll()
    {
        var tasks = await _taskService.GetAllAsync();
        return Ok(tasks);
    }

    [HttpGet("{id}")]
    public async Task<IActionResult> GetById(Guid id)
    {
        var task = await _taskService.GetByIdAsync(id);

        if (task == null)
            return NotFound();

        return Ok(task);
    }

    [HttpPost]
    public async Task<IActionResult> Create(CreateTaskDto dto)
    {
        var task = await _taskService.CreateAsync(dto);

        return CreatedAtAction(
            nameof(GetById),
            new { id = task.Id },
            task);
    }

    [HttpPut("{id}")]
    public async Task<IActionResult> Update(Guid id, UpdateTaskDto dto)
    {
        await _taskService.UpdateAsync(id, dto);
        return NoContent();
    }

    [HttpDelete("{id}")]
    public async Task<IActionResult> Delete(Guid id)
    {
        await _taskService.DeleteAsync(id);
        return NoContent();
    }
}
```

### FluentValidation Rules

```csharp
public class CreateTaskValidator : AbstractValidator<CreateTaskDto>
{
    public CreateTaskValidator()
    {
        RuleFor(x => x.Title)
            .NotEmpty()
            .MaximumLength(100);

        RuleFor(x => x.Description)
            .MaximumLength(1000);

        RuleFor(x => x.DueDate)
            .GreaterThan(DateTime.UtcNow);
    }
}
```

## 4. Improvements and Corrections Made

Although the generated solution was functional, manual improvements were necessary before considering it production-ready.

### 4.1 Ownership Validation

#### Issue

The generated version allowed authenticated users to retrieve tasks belonging to other users.

#### Improvement

Ownership checks were added.

```csharp
if (task.UserId != currentUserId)
{
    throw new ForbiddenException();
}
```

#### Benefit

Ensures users can only view and manage their own tasks.

### 4.2 Global Exception Handling

#### Issue

The generated code contained repetitive exception handling inside controllers.

#### Improvement

Implemented centralized exception middleware.

```csharp
app.UseMiddleware<GlobalExceptionMiddleware>();
```

#### Benefit

- Consistent API responses.
- Cleaner controllers.
- Easier maintenance.
- Centralized logging.

### 4.3 Pagination Support

#### Issue

The generated API returned all tasks without limits.

#### Improvement

Added pagination support.

```http
GET /api/tasks?page=1&pageSize=20
```

#### Benefit

- Better scalability.
- Improved performance.
- Reduced bandwidth usage.

### 4.4 Repository Enhancements

#### Issue

Generic repository methods were insufficient for common queries.

#### Improvement

Added task-specific methods.

```csharp
Task<IEnumerable<TaskItem>> GetByUserIdAsync(string userId);
```

#### Benefit

Provides a more expressive and maintainable data access layer.

### 4.5 Additional Validation Rules

#### Issue

Generated validations were minimal.

#### Improvements Added

- Maximum title length.
- Maximum description length.
- Due date validation.
- Allowed status transitions.
- Optional title uniqueness per user.

Example:

```csharp
RuleFor(x => x.Description)
    .MaximumLength(1000);
```

## 5. Authentication, Authorization, Validation, and Edge Cases

### Authentication

The API uses JWT Bearer Authentication.

#### Authentication Flow

1. User authenticates.
2. JWT token is generated.
3. Token is included in requests.
4. Middleware validates the token.
5. User claims are used for authorization checks.

Example request:

```http
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

### Authorization

A user can only manage tasks associated with their account.

Example policy:

```csharp
services.AddAuthorization();
```

All task endpoints require authentication.

```csharp
[Authorize]
```

### Input Validation

#### Title

Requirements:

- Required.
- Maximum 100 characters.

#### Description

Requirements:

- Optional.
- Maximum 1000 characters.

#### Due Date

Requirements:

- Required.
- Must be greater than the current date.

#### Status

Accepted values only:

```text
Pending
InProgress
Completed
```

Invalid values return:

```http
400 Bad Request
```

### Edge Cases Considered

#### Task Not Found

Request:

```http
GET /api/tasks/{id}
```

Response:

```http
404 Not Found
```

#### Invalid Request Data

Examples:

- Empty title.
- Invalid status.
- Due date in the past.

Response:

```http
400 Bad Request
```

#### Missing Authentication

Request made without a token.

Response:

```http
401 Unauthorized
```

#### Accessing Another User's Task

Attempting to retrieve or modify another user's task.

Response:

```http
403 Forbidden
```

#### Concurrent Updates

To prevent overwriting changes from simultaneous updates, optimistic concurrency control can be implemented.

Example:

```csharp
public byte[] RowVersion { get; set; }
```

Benefit: avoids accidental data loss when multiple users edit the same task simultaneously.

#### Large Data Sets

Pagination was introduced to handle large numbers of tasks efficiently.

```http
GET /api/tasks?page=1&pageSize=20
```
